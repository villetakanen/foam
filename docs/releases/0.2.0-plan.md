# FOAM 0.2.0 delivery plan

Current status (2026-09-24): mechanically verified; the project owner accepts the
partial-recollection evidence as sufficient for experimental 0.2. Release version: `v0.2.0` (2026-09-24).
See the [current release decision](0.2.0-evaluation.md) and
[vision](../../VISION.md). Known limitations remain visible in the evaluation review.

The plan below preserves the original implementation scope and historical semantic
criteria. Its old numerical and activity-completeness gates are superseded; they are
not additional conditions on the accepted experimental release.

## Outcome

Make FOAM useful and inspectable as a small, project-owned working memory across Pi,
LangGraph and embedded clients such as ACK. A healthy scratchpad is not sufficient:
the evoked view must preserve what the conversation is about and help continuation
without inventing obligations or reviving completed work.

Inputs: the [roadmap](../../ROADMAP.md), [ACK field feedback](../feedback/2026-09-23-ack.md),
[0.1.0 evaluation](../evaluation.md), and the observed interrupted Pi run that left a
writer lock. ACK's report is supplied evidence, not an independently inspected audit.
Its 18 abandoned operations are not assumed to be lock failures.

## Release scope and boundaries

Ship project configuration, grounded encounter handling, output-envelope compatibility,
inspectable operations, safe local recovery, and a repeatable semantic evaluation.
Keep Markdown as authoritative memory and preserve `prepare`, `observe`, `inspect`
and direct in-process inference adapters. Access may change memory. Analyze the whole
authorized working set while keeping the returned context independently bounded.

Host applications own durable pending tasks, confirmations, retries of external actions
and tool execution. FOAM can remember a request's meaning and referent without owning
its execution state. Scope remains an explicit host binding, never model-inferred.

No mandatory HTTP server, task ledger, per-claim confidence database, vector index,
distributed synchronization, automatic conversation rewind or autonomous memory loop.
A model failure must not silently trigger a paid/cloud fallback or change data exposure.

## Delivery sequence

| Step | Deliverable | Depends on | Completion evidence |
| --- | --- | --- | --- |
| 1 | Reproducible failure scenarios and scoring rubric | Existing reports | Frozen synthetic cases and baseline traces before prompt tuning |
| 2 | Shared schema and bounded JSON-envelope decoder | 1 | Parser and custom-adapter contract tests |
| 3 | Project configuration and migration | 1 | Same scope opened by Pi, LangGraph and an embedded client |
| 4 | Encounter inputs and operation diagnostics | 2, 3 | Correlated prepare/supply/observe traces and bounded inspection |
| 5 | Grounded memory policy and small-model evaluation | 1, 2, 4 | Scored identity, relevance, continuity and completion trials |
| 6 | Interrupted-run recovery | 3, 4 | Subprocess termination and live-writer contention tests |
| 7 | Integration, documentation and release | 1–6 | Release gates below, clean installation and recorded limitations |

Implement each step as a reviewable change with its contract and verification. Change
`specs/memory/spec.md` alongside implementation; this plan does not describe existing
0.1.0 behaviour. Steps 2 and 3 are independent once the scenarios are recorded.

## 1. Establish evidence before changing policy

Add synthetic scenarios under `tests/fixtures/` and an evaluation runner under `examples/`.
Retain the 0.1.0 results and keep tuning cases separate from held-out evaluation cases.

Cases must cover:

- Radiator identity and installation dimensions through compaction and repeated access.
- A description followed by “update the note with that,” both in one observation and
  across successive encounters. A host task stub is identical in all conditions.
- Older sensor readings competing with the current purchase in the same scope.
- Interruption by an unrelated activity, then return to either activity.
- Explicit completion followed by repeated old cues, without invented verification work.
- Ambiguous references, negation, partial completion and corrections. Asking for
  clarification is correct when the supplied evidence does not resolve the reference.
- Empty memory, fresh-process restart, explicit scope separation and an oversized input.

Define expected preserved facts and acceptable continuations independently of model
wording. Score stored Markdown, returned context and the responding client's behaviour
separately. Do not treat a keyword match or a valid JSON response as semantic success.
Use fictional details, not ACK's household transcript or private scratchpad.

## 2. Make output handling reusable

Add a shared response schema and decoder, exported from the package. The reference HTTP
adapter and embedded adapters can use them; core validation remains authoritative.

The decoder accepts plain JSON or one complete JSON object inside one Markdown code
fence (empty or `json` label), with optional surrounding whitespace. Bound the raw
input before parsing. Reject commentary, multiple blocks, truncation, malformed JSON,
wrong fields and wrong types. Strip only the envelope: never repair content, guess a
substring or bypass scope/size/revision checks. Report whether normalization occurred.

Test plain/fenced equivalence and every rejection class through the HTTP adapter and
an in-process fixture. Preserve committed bytes on failure. A structured-output request
is a provider capability request, not a guarantee of either syntax or factual accuracy.

## 3. Let the project own setup

Planning default: a versioned, shareable `foam.config.json` at the project root and
ignored runtime state under `.foam/<scope-name>/`. Document the filename/schema as part
of implementation before exposing it as a stable interface.

Configuration describes named scopes, project-relative memory directories, budgets,
policy version and inference configuration. Store credential environment-variable names,
never credentials. Application code can inject an adapter instead of a configured HTTP
backend. Avoid arbitrary executable module loading from configuration.

Provide `openProjectMemory({ projectRoot, scope, inference? })` as the planned common
entry point, while retaining the explicit `new Foam(...)` path for application scopes
such as a household. Pi passes its current project root; LangGraph and ACK pass theirs
explicitly. No parent-directory search that silently crosses into another project.

Scope names must map to declared directories beneath the configured memory root;
reject traversal, aliases to another scope and unsafe symlink escapes. Configuration
is not an operating-system security boundary: the embedding host authenticates users
and authorizes the scope it opens. Do not claim client-name labels enforce access.

Add an explicit initializer and status command. Initialization creates configuration
and the `.foam/` ignore rule without overwriting existing files or discarding settings.
Existing environments/directories remain usable. Define precedence explicitly: direct
constructor options remain authoritative; project mode reads project configuration;
legacy environment mode is selected explicitly rather than silently overriding it.

Migration validates the old scope and revision, preserves Markdown and leaves source
state untouched until the new setup is verified. Allow the existing `.foam/private/`
layout without a forced move. Show active configuration, directory, scope and backend.

## 4. Preserve encounters and expose what happened

Extend the normalized encounter contract additively with bounded recent exchange data
and host correlation/source references where needed. Keep user statements, assistant
claims and tool outcomes distinguishable. Correlation connects a request to its supplied
facts; it is not an instruction to merge every turn into one activity. Missing recent
context must remain visible rather than being invented by FOAM.

Pi, LangGraph and embedded examples must map the same synthetic exchange to equivalent
policy inputs. Preserve revision/checkpoint protections and the explicit report of
supplied context. Supply is an adapter observation, not proof of model attention.

Add an optional host diagnostics sink with operation ID, client correlation, scope,
phase, revisions, duration, normalization, failure reason and commit outcome. Detailed
capture includes supplied context and before/after Markdown only when enabled. Reuse
ACK's audit through the sink; do not require another history store.

For local inspection, provide bounded opt-in trace storage under the scope's runtime
directory. Specify byte/count limits and rotation; never feed diagnostic history back
as memory automatically. Inspection should work without calling the inference model.
Pi's view and a client-neutral status/inspection command use the same records.

Diagnostic failures must not turn a successful memory commit into a misleading failed
memory operation. Make any diagnostic loss explicit. Distinguish prepare failure,
observation failure after a successful prepare, and a commit whose result was lost.

## 5. Improve the policy and measure small models

Start with the existing complete-Markdown response contract, a shorter grounded prompt
and the improved encounter inputs. Preserve entity identity and fact relationships;
choose context for the current subject while retaining unrelated activities unless
there is evidence to release them. Do not manufacture new tasks from reminders.

Use the existing E4B result as historical evidence, then rerun it under the same current
harness as smaller candidates. Screen Qwen3 0.6B/1.7B and Gemma E2B using available,
verified model identifiers and explicit non-thinking settings where supported. These
are candidates, not preselected winners or guaranteed runtime features.

Use a 100-line, approximately 80-character-per-line Markdown fixture for the larger
small-memory case. Measure actual tokenizer counts where available; the approximate
8 KB / 2,000-token estimate is not a portable token limit. Include full instructions,
encounter input and output reserve in admission checks. Record model/version, runtime,
quantization, sampling, thinking settings, hardware, warm/cold latency and output size.

A patch/edit response is an experiment if whole-file generation causes excess latency
or unrelated-content loss. Compare both on the same cases before changing the public
contract or storage semantics. Patches would still need validation and atomic application.
Apple Foundation Models integration is optional follow-on work, not a 0.2.0 dependency.
Do not infer a required model size from one failed prompt or a requirement for a larger
model from invalid JSON alone.

## 6. Recover from interruption safely

Replace anonymous locks with an ownership-aware local coordination design. Record an
operation identity and enough process identity to avoid treating a reused PID as the
original writer. Choose and document the lock primitive after proving safe acquisition
and recovery under subprocess tests; ordinary check-then-delete is not sufficient.

Expose busy-owner diagnostics and an explicit recovery operation. Never steal a live
lock or use elapsed time as proof of abandonment. Unknown ownership, foreign hosts
and legacy empty locks require explicit operator verification. Keep the legacy repair
path documented rather than guessing that an empty directory is abandoned.

Test termination before inference completes, before rename, after rename and before
result delivery, plus two recovery contenders and a live writer. After recovery, memory
must be one complete old or new committed snapshot and subsequent writes must succeed.
Keep local-filesystem scope; no network/distributed locking promise.

Report ambiguous outcomes without blindly retrying: repeated real encounters are valid
and may change memory, so recovery must not introduce implicit cognitive deduplication
or double-apply an operation whose commit already happened.

## Release gates

The following are initial release acceptance targets, to freeze with the scoring rubric
before implementation tuning. Report raw counts and failures; these sample sizes do not
establish a general reliability percentage or scientific superiority.

- All deterministic contract, adapter, configuration, decoder and recovery tests pass.
  Run `npm run check` and both demos, plus any added targeted verification.
- On at least one documented small local model/configuration, run 20 held-out radiator
  continuation trials and 20 completion/old-cue trials. Require zero entity substitutions,
  dimension reassociations, invented obligations or obsolete action suggestions in these
  focused trials. Require a useful grounded continuation in at least 18/20 radiator
  trials, including appropriate clarification in the deliberately ambiguous cases.
- Across ten sequences of ten repeated accesses, preserve unrelated ongoing activities
  in memory while omitting irrelevant content from the current view. Review accumulated
  drift, not only the last response. Failures block a claim that this criterion passed.
- Compare FOAM enabled/disabled with the same responding model, project context and host
  task state. Publish outcomes without claiming an advantage unless the comparison
  supports it. Protocol failures count as failures, not discarded samples.
- Publish p50/p95 preparation and observation latency, cold-start latency, calls, bytes
  and available token counts. Provisional interactive target: warm p95 preparation under
  3 seconds on the recorded reference machine. If unmet, mark the result as unsuitable
  for that interactive profile and narrow the release claim or revisit the design;
  do not hide latency behind a smaller output limit that truncates responses.
- Pi and a real LangGraph graph pass fresh-project setup and continuation checks. A
  custom in-process client demonstrates the same semantics without HTTP. Offer ACK a
  focused retest; if not run, label application acceptance unverified rather than claiming it.
- Migrate an existing 0.1.0 scratchpad without losing scope, revision or content. Install
  the packed artifact in a clean consumer. Audit package contents for private data and
  credentials. Pin tested host versions and provide quickstarts and recovery instructions.
- Update the living spec, architecture decisions as needed, README, changelog and
  evaluation report. Publish 0.2.0 only after the gates pass or the release scope and
  unmet criteria are explicitly reconsidered; do not silently lower the rubric.

## Deferred and unresolved

Deferred: Apple/Swift runtime integration, automatic Codex-subscription-backed memory,
mandatory patch-based writes, fine-tuning, a durable task system and additional clients.

Resolve during the relevant step: final configuration schema and CLI names; bounded
recent-exchange shape; diagnostic retention defaults; safe portable lock primitive;
reference small-model/runtime choice. These decisions do not require collecting private
ACK data or installing every candidate before the test harness exists.
