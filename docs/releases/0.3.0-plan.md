# FOAM 0.3.0 — use the host's model

Status: planned, 2026-09-25. No implementation or release claim.

## Outcome

Enable FOAM in an existing Pi or LangGraph agent without configuring a second model
service. FOAM uses the host's model and authentication for separate memory calls.
A dedicated inference backend remains an explicit option. Memory still serves the
[vision](../../VISION.md): useful, partial contextual awareness.

The motivating failure in 0.2 was setup friction: a Pi user had a working session
model but also needed a FOAM endpoint, model configuration and running Ollama server.
The 0.3 acceptance example is enabling memory with the existing host model and an
explicit memory scope, then continuing after a context reset without that extra setup.

## Backend selection and compatibility

Preserve the current precedence and add a final host fallback:

1. Explicit programmatic `InferenceAdapter`.
2. Explicit project `inference` configuration.
3. Host-provided inference, when available.
4. A clear setup error when none is available.

Implement this in project binding with an optional host adapter, rather than treating
the host default as the existing explicit override. Otherwise it would accidentally
bypass configured project backends. Keep direct `new Foam(...)` injection and legacy
environment mode working. Standalone clients still choose their own backend.

Existing 0.2 configurations continue using their configured endpoint. To opt into the
host model, remove the project `inference` entry; scope and stored memory stay intact.
Do not silently migrate a local backend to a remote host model. Backend errors must
not trigger an automatic switch to another provider or model.

## Pi integration

- Resolve the active session model for each memory operation, using Pi's provider
  invocation and authentication facilities, including resolved headers and credential
  refresh. Do not copy credentials into FOAM configuration or diagnostics.
- A model switch affects the next operation; capture one model choice for an in-flight
  call. Changing model does not reset memory or change authorization scope.
- Invoke the provider directly for memory interpretation, not another agent turn.
  Keep memory prompts, generated text and tools outside the visible transcript.
  Do not recursively trigger FOAM's context/observation hooks.
- When no model/auth is available, explain the actual cause and let Pi continue without
  stale injected memory. `/foam` should expose the backend selection and retain the
  last initialization failure instead of only saying “project is not open.”

The installed Pi SDK exposes `ctx.model` and `ctx.modelRegistry.getApiKeyAndHeaders`.
First verify the supported invocation path for built-in and registered providers;
sharing a model name alone does not establish authentication or provider compatibility.
Test both the currently supported 0.86 line and the user's 0.87 line before updating
the peer range. Do not promise compatibility based on matching types alone.

## LangGraph integration

- Provide a small adapter for an application's existing chat model or model-calling
  function. Reuse its configured authentication and transport without asking for a
  second FOAM model configuration.
- The application chooses the model: a graph can contain several. For routed models,
  permit a caller-owned resolver or callback that selects the backend per invocation.
  Do not infer a model from graph state or inspect the graph to guess one.
- Supply only FOAM's instruction and bounded evidence to the memory call. Do not
  invoke the compiled agent graph or execute its tools. Document passing the underlying
  model rather than a tool-bound agent when necessary.
- Carry cancellation and applicable invocation configuration through the adapter.
  Give memory calls distinct tags/metadata so graph streams and callbacks can separate
  them from user-visible output. Test that the example actually performs this filtering.
- Keep `memoryNodes(foam)` and checkpoint behavior compatible. Put optional LangChain
  dependencies at the adapter boundary; the portable core must remain host-independent.

## Shared response and execution contract

Adapt provider output through the existing bounded decoder and interpretation schema.
Use structured output where the host supports it; otherwise request the same JSON
envelope and validate it. Reject truncated, malformed, oversized or tool-only replies
without changing memory. Do not execute proposed tools or add automatic repair turns.

Preserve timeout, abort, byte budgets, revision checks and atomic writes. FOAM makes at
most one adapter invocation per operation; document SDK retry behavior and disable it
where supported. Reusing the host model still consumes additional calls, time and quota.
Report backend source, model/provider identity when available, duration and failures
without exposing credentials. Reuse model/provider configuration; keep memory-specific
output limits explicit rather than inheriting an unlimited agent/tool loop.

## Implementation sequence

1. **Verify host APIs and dependency boundaries.** Prove a bounded independent call
   through Pi's current model/auth and a LangChain model; select supported versions.
2. **Add backend fallback selection.** Preserve explicit-adapter/project precedence,
   no-backend errors, legacy behavior and inspection without inference. Update the spec.
3. **Wire Pi host inference.** Cover initialization, model changes, authentication,
   cancellation, failure reporting and absence of recursive or visible agent turns.
4. **Add LangGraph model adapter.** Cover static and caller-routed models, invocation
   config, tool isolation and separation of memory output from application streaming.
5. **Update setup and migration examples.** Show host-model setup first and a dedicated
   endpoint as an override. Explain extra usage, scope, supported Pi versions and how
   to leave an existing local backend unchanged.
6. **Verify and release.** Run checks below; record limitations, build and install the
   package in clean consumers, then prepare the 0.3 release. Publishing is a later action.

## Acceptance checks

| Check | Required evidence |
| --- | --- |
| Pi default | An actual Pi SDK session supplies its configured model/auth; FOAM works with no project inference entry, FOAM endpoint variables or Ollama service. |
| Pi model switch | Next memory operation uses the new selection; existing memory and scope survive. |
| LangGraph default | An executing graph shares its configured model with FOAM through the adapter, without another endpoint or credentials. |
| Overrides | Explicit adapter wins over project backend; project backend wins over host fallback. A failing override never silently falls back. |
| Failure behavior | Missing model/auth, abort, timeout, invalid output and provider error preserve memory and report the cause. Pi can continue; graph failure handling stays explicit. |
| Isolation | Memory calls do not appear as assistant replies, invoke tools, recurse through the graph, or cross configured scopes. |
| Useful recollection | Replay the epic reset and pool-hours probes through the host adapters. Credit a useful association or focused question; no completeness threshold is introduced. |
| Release mechanics | `npm run check`, both demos, clean package/CLI installation and CI pass; verify documented Pi versions and the graph integration. |

Use deterministic provider doubles to verify routing, authentication forwarding and
failure cases. Also record a bounded real-provider smoke run for each host path; a
scripted response alone does not prove provider compatibility. Report separate memory
contribution and client uptake, following the existing partial-recollection rubric.

## Outside this release

No new forgetting mechanism, memory schema, task ledger, chat transport, provider
fallback service or semantic-policy retuning is required. This release removes host
integration friction while preserving FOAM's current memory experiment. Remaining
provider-specific limitations should be documented with a precise supported path.


## Implementation status — 2026-09-25

Implemented the host fallback, Pi registry adapter, LangGraph model/callback adapter,
backend inspection/diagnostics, setup/migration documentation and shared-model graph
example. The memory policy remains version 0.2.

Local verification: 47 tests, build and type checks; both existing demos and the
shared-model graph example; actual Pi SDK sessions on 0.86.0 and 0.87.0; clean tarball
installation, CLI initialization/inspection and host-adapter execution without runtime
Pi/LangChain dependencies. Provider doubles cover host auth/header forwarding and
model switching. Live local-provider evidence is recorded separately in the
[host-model evaluation](../evaluations/2026-09-25-host-models.md).

Hosted-provider/OAuth flows are not live-tested. CI on a pushed revision, tagging and
publication remain release actions; this implementation does not claim they ran.


Release authorized on 2026-09-25. Local checks are complete; the release procedure
requires successful CI for the published commit and an attached, verified package.
Distribution continues through GitHub releases, not the npm registry.
